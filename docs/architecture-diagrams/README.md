Дата анализа: 2026-10-22. Ветка на момент анализа: `w2-shared-foundations` (локальная, не запушена в `origin/main` — см. диаграмму 4).

> **Обновление 2026-10-28.** Диаграммы — снимок состояния на 2026-10-22. Утверждения о git (пункт 4 ниже и диаграмма 4: «всё существует только локально») устарели: вся работа теперь в ветке `fix/android-sdk58` на GitHub. Актуальное состояние веток и приложений — в [`HANDOVER.md`](../../HANDOVER.md).

Эта папка — результат анализа **фактического состояния кода** (не планов и не документации) четырёх приложений Mmusic: `apps/mobile`, `apps/web`, `apps/arm`, `apps/crm`, плюс их общих пакетов и backend-заготовки `apps/api`. Диаграммы показывают, как экосистема выглядит **сегодня**, с явной отметкой того, что только запланировано.

## Как читать диаграммы

- **Сплошные цветные блоки** = подтверждено в коде (implemented).
- **Пунктирные блоки / пунктирные связи** = не реализовано, мок-данные или не проверяемо локально (planned / mock / unverified) — всегда с пояснением, почему.
- **Цвета**: синий = Mobile, зелёный = Website, оранжевый = ARM, фиолетовый = CRM, серый = общие пакеты, бирюзовый = хранение данных.

## Экспорт в SVG/PNG

Если нужны именно файлы `.svg`/`.png` — с вашего одобрения можно выполнить (разово, без постоянной установки):

## Что НЕ подтверждено / архитектурные пробелы

Это главное, что стоит знать перед презентацией руководству:

1. **`apps/api` — пустая заготовка.** NestJS-скелет из 6 файлов (`hello-world` + `/health`). Нет БД, нет бизнес-роутов, нет авторизации. Ни одно из 4 приложений не вызывает его сегодня.
2. **Авторизации нет нигде.** В коде `apps/arm/src/access.tsx` и `apps/crm/src/access.tsx` прямо написано: матрица прав — *«Prototype only — not authentication or security»*.
3. **Общей базы данных нет.** Все 4 приложения — изолированные острова с данными в `localStorage`. ARM/CRM используют **другой** storage-слой (`packages/backoffice/storage.ts`), не тот, что mobile/web (`core/platform/storage.ts`).
4. **Git remote есть, но сильно отстаёт.** `origin` = `github.com/imashevvva2999-cmyk/asdasdd11aisdasdj`, но там `main` — это коммит `f40b8f1`, **до** появления `apps/web`, `apps/arm`, `apps/crm`. Всё текущее состояние существует только в этой локальной копии — её потеря означает потерю всей этой работы.
5. **Деплой закоммичен только для `apps/mobile`** (`apps/mobile/vercel.json` + `.vercel/project.json`, проект «mobile»). Упомянутые в прошлых сессиях `mmusic-web/arm/crm.vercel.app` — это ручные `vercel deploy` из scratchpad-копий; в репозитории нет конфигурации под них, и их текущий live-статус не проверяем локально.
6. **Нет CI/CD** — ни одного файла `.github/workflows`; все деплои до сих пор ручные.
7. **Модель данных CRM** (артисты как юрлица, группы, организации, сделки) **не описана в `docs/architecture.md`**. Это полезный прототип, но формально он не часть утверждённого ТЗ — там есть только подтверждённый, но не спроектированный модуль «Admin Panel» (FR-19.1, OQ-54). Стоит явно сверить назначение ARM/CRM с этим требованием, чтобы не расходиться с будущим backend-дизайном.
