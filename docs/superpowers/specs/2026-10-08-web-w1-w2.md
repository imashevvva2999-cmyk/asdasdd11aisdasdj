## 2. W2 — звук в браузере

### 2.1. Проблема

Раньше на сайте работал веб-плеер `expo-audio`. Он создаёт **новый** `<audio>` при каждой смене трека.

В iOS Safari элемент может начать воспроизведение без нового касания, только если **этот же** элемент уже запускался по жесту пользователя. Поэтому были под угрозой три сценария:
- отложенный (180 мс) старт после свайпа обложки;
- автопереход к следующему треку;
- кнопки экрана блокировки.

### 2.2. Решение

| Файл | Что делает |
|---|---|
| `src/audio/browser-audio-engine.ts` | **Один `<audio>` на всю сессию**, для каждого трека меняется только `src`. Первый жест пользователя (касание, клик, клавиша) «разблокирует» элемент коротким беззвучным клипом, если настоящий трек ещё не загружен. `NotAllowedError` превращается в статус `blocked`, а не в ошибку. `AbortError` (более новый `load`/`pause`) игнорируется. Статусы приходят 4 раза в секунду во время игры |
| `src/audio/media-session.ts` | Экран блокировки, уведомление, гарнитура, медиа-клавиши. Показывает название, артиста, альбом, обложку и позицию. Действия Play/Pause/Previous/Next/перемотка вызывают те же функции store, что и кнопки приложения. Неподдерживаемые действия не ломают привязку |
| `src/audio/platform-audio.web.ts` | Запуск на сайте: создаёт скрытый `<audio id="mmusic-audio">`, подключает движок и Media Session (если браузер его поддерживает) |
| `src/audio/platform-audio.ts` | Нативная сборка — как раньше, `expo-audio` (код сохранён, не удалялся) |
| `src/audio/demo-sources.ts` | Общая карта демо-треков для обеих реализаций |
| `src/state/player-store.ts` | Статус `blocked` → плеер показывает **паузу** вместо бесконечной загрузки; одно нажатие Play запускает трек |

URL аудиофайлов вычисляет та же функция, что и у `expo-audio` (`getSourceUri`), поэтому новой зависимости нет.

## 3. W1 — веб-фундамент

### 3.1. Маршрутизация, прямые ссылки, обновление страницы, «назад» и «вперёд»

`scripts/serve-web.mjs` — сервер продакшен-сборки на встроенных модулях Node. Он же **эталон правил для любого будущего хостинга**:

| Правило | Пример |
|---|---|
| Чистые URL | `/home` → `home/index.html`, `/player/now-playing` → `player/now-playing.html` |
| Прямые ссылки на динамические страницы | `/artist/solaris-echo` → предрендеренная страница; `/artist/<любой id>` → шаблон `artist/[id].html` (200) |
| Всё остальное | 404 со страницей `+not-found.html` (копия — `404.html`) |
| Служебные пути | Папки групп `(tabs)` и файлы-шаблоны `[id]` по прямому адресу не отдаются |
| **HTTP Range** | `Accept-Ranges: bytes`, ответы 206 и 416 — без этого Safari не играет и не перематывает аудио |
| Кеширование | HTML — `no-cache`; файлы с хешем (`/_expo`, `/assets`) — на год, `immutable` |
| Безопасность | `nosniff`, `Referrer-Policy`, запрет встраивания во фрейм (`frame-ancestors 'none'`, `X-Frame-Options`), `Permissions-Policy`; защита от выхода за пределы папки; только GET и HEAD |

### 3.2. Метаданные и safe-area

- **`src/app/+html.tsx`** — HTML-документ каждой страницы:
  - `lang="en"` (язык интерфейса);
  - `viewport-fit=cover` — настоящие отступы под вырез и полосу «Домой» на iPhone;
  - масштабирование не запрещено;
  - описание, `theme-color`, Open Graph, манифест, иконка для экрана «Домой»;
  - фон `#0A0A0C` на `html`/`body`, без белых вспышек при прокрутке за край.
- **Заголовки страниц** (`components/web/route-title.tsx`, `lib/page-title.ts`):
  - примеры: «Solaris Echo – Mmusic», «Midnight Mirage by Solaris Echo – Mmusic», «Your Library – Mmusic»;
  - видны во вкладках, в истории браузера и при шаринге.
- **Манифест** `public/manifest.webmanifest` и иконки `public/icons/*` — сайт можно добавить на экран «Домой».
  - Иконка — **временная**: знак эквалайзера из шапки приложения, коралловый на тёмном фоне. Нужно утвердить у дизайнера (§6, вопрос 1).
  - Фавиконка Expo заменена.
- Брендинг MBANK в метаданные не добавлялся.

### 3.3. Dev-страницы и 404

- `/dev-ui-kit` и `/_sitemap`: вне режима разработки показывают 404. Из продакшен-сборки их файлы удаляются (`scripts/web-postexport.mjs`). В разработке оба доступны, как раньше.
- `src/app/+not-found.tsx` — страница «Page not found» в стиле приложения с кнопкой «Go to Home».

### 3.4. Новые команды

```
cd apps/mobile
pnpm build:web      # продакшен-сборка в dist/ (expo export + удаление dev-страниц + 404.html)
pnpm preview:web    # сервер продакшен-сборки: http://127.0.0.1:8090
```

### 4.2. В браузере (Chromium, 390 × 844, продакшен-сборка через `preview:web`)

- **Прямые ссылки и обновление страницы:**
  - Home, Artist, Album, Playlist, жанр, Now Playing (в том числе `?trackId=horizon`), Lyrics, Queue, Liked Songs, Settings, лист Demo audio, `/track/horizon` → плеер;
  - везде статус 200 и правильный заголовок;
  - `/dev-ui-kit` и неизвестный путь → 404 «Page not found».
- **«Назад» и «вперёд»:**
  - Home → Library → Artist → плеер;
  - «назад» сворачивает плеер, «вперёд» открывает снова, дальнейшие переходы корректны.
- **Звук:**
  - Play → играет;
  - перемотка тапом по шкале → браузер запрашивает Range (`bytes=0-`, `bytes=5734400-`), сервер отвечает 206, позиция 180 с, воспроизведение продолжается;
  - свайп на следующий трек → играет, всё время **один** `<audio>`.
- **Имитация политики Safari** (запуск разрешён только элементу, уже запущенному жестом): первый свайп без нажатия Play, свайп назад с отложенным стартом, автопереход в конце трека — **0 отказов**.
- **Полная блокировка браузером:** плеер показывает Play, без вечной загрузки и без сообщения об ошибке.
- **Media Session:** название, артист, обложка (абсолютный URL), состояние playing/paused.
- **Регрессия мобильного плеера:** свайп мини-плеера, раскрытие свайпом вверх, карусель, сворачивание вниз — без изменений.

## 5. Оставшиеся риски Safari и браузеров

| # | Риск | Статус |
|---|---|---|
| 1 | **Реальный iPhone не проверялся.** Политика автозапуска WebKit имитировалась в Chromium. Разблокировка одним элементом — стандартный приём, но подтверждение нужно на устройстве (§7) | Проверить первым делом |
| 2 | **Media Session требует безопасного контекста (HTTPS).** По `http://<IP Mac>` с телефона управление с экрана блокировки может не появиться — это не ошибка. Полная проверка — на staging с HTTPS | Ожидаемо |
| 3 | **Фоновое воспроизведение** при заблокированном экране и после переключения приложений на iOS | Проверить на устройстве |
| 4 | **Громкость на iPhone** задаётся только системой (ограничение платформы). В W1/W2 слайдера громкости нет, поэтому сейчас это ни на что не влияет | Учесть в W3 |
| 5 | **Ошибка гидрации React #418** на всех страницах продакшен-сборки. **Существовала и до W1/W2** (проверено на сборке без изменений W1). Вероятная причина: корневой layout возвращает `null`, пока грузятся шрифты, а статический HTML отрисован целиком; React пересобирает страницу на клиенте. Функционально всё работает, но первый показ дороже | Отдельное исправление — по вашему решению (§6) |
| 6 | **Свайп от левого края в Safari** — системный «назад». Плеер при этом корректно сворачивается, но конфликт ощущений нужно проверить | Проверить на устройстве |
| 7 | **Однократное наблюдение:** в одном прогоне после перемотки трек оказался на паузе. В 8 повторах подряд (в том числе в чистом браузере) не воспроизвелось | Наблюдать при ручной проверке |
| 8 | **Размер JS** (≈ 764 КБ gzip) и шрифты TTF — не входили в W1/W2 | Отдельная оптимизация |
| 9 | **Правила `serve-web.mjs` нужно перенести на выбранный хостинг:** переписывание URL, 404, Range, заголовки, кеш | При выборе хостинга (W9) |

## 6. Вопросы на ваше решение

1. **Иконка сайта и фавиконка** — утвердить временный знак (коралловый эквалайзер) или получить макет от дизайнера.

## 7. Как проверить в браузерах

### 7.1. На Mac

```
cd "/Users/kalemaimasheva/Desktop/Mmusic app/apps/mobile"
pnpm build:web
pnpm preview:web
```

Открыть `http://127.0.0.1:8090` в Safari и Chrome (и в Firefox, если есть).

### 7.2. С iPhone и Android в той же Wi-Fi-сети

```
node scripts/serve-web.mjs dist --host 0.0.0.0 --port 8090
```

На телефоне открыть `http://<IP Mac>:8090`. IP Mac показывает команда `ipconfig getifaddr en0`; в прошлый раз это был `10.0.100.116`.

Сервер слушает все интерфейсы только пока запущен. Остановить — Ctrl+C.

### 7.3. Чек-лист

1. **Обновление и ссылки.** Открыть и обновить (⌘R или потянуть вниз) `/home`, `/artist/solaris-echo`, `/album/horizon-deluxe`, `/player/now-playing`, `/player/lyrics`, `/player/queue`. Страница та же, вкладка с правильным заголовком. Адрес `/abc` → «Page not found» → «Go to Home».
2. **«Назад» и «вперёд».** Home → Library → артист → открыть плеер. Кнопка «назад» сворачивает плеер, «вперёд» открывает. На iPhone попробовать и свайп от края.
3. **Звук на iPhone (главное):**
   1. ничего не нажимая, открыть плеер и **сразу свайпнуть обложку** — трек должен заиграть (Horizon);
   2. свайпнуть назад — играет Midnight Mirage;
   3. перемотать почти до конца — после окончания сам заиграет следующий трек;
   4. несколько быстрых свайпов — играет только последний трек, двух звуков одновременно нет;
   5. остальные треки показывают «No audio in this preview».
4. **Перемотка.** Перетащить ползунок и тапнуть по шкале — звук продолжается с нового места.
5. **Экран блокировки** (лучше по HTTPS на staging): заблокировать телефон во время игры — звук продолжается, на экране название и обложка, работают Pause / Play / Next / Previous. Наушники: кнопка паузы.
6. **Safe-area на iPhone с вырезом.** Шапка и нижние вкладки не заходят под вырез и полосу «Домой». Повернуть телефон.
7. **«На экран „Домой“».** В Safari: «Поделиться» → «На экран „Домой“». Иконка Mmusic; запуск открывает Home без адресной строки.
8. **Жесты плеера на телефоне:** свайп мини-плеера влево/вправо, свайп вверх для раскрытия, свайп обложки, pull вниз для сворачивания.
9. **Mac Safari и Chrome:** то же, плюс медиа-клавиши клавиатуры (Play/Pause, Next).
10. Отметить, что звучит не так или выглядит иначе.
