# Фаза 2 — Реальное аудио: техническая спецификация

**Статус:** на утверждении. Код не меняется, зависимости не ставятся и аудио не скачивается до одобрения.
**Дата:** 2026-10-08. **Основа:** коммит `4cc4a5e` (Фаза 1).

## 1. Цель и критерии успеха

Заменить имитацию воспроизведения (таймер `setInterval` в `src/state/player-store.ts`) настоящим воспроизведением звука через `expo-audio` для 2 лицензированных демо-треков.

Критерии успеха:
1. Два каталожных трека реально звучат на Expo Web (и в Expo Go, если пользователь проверит на телефоне).
2. Play/Pause, Next/Previous, прогресс и перемотка управляют реальным звуком; позиция берётся из аудио-движка, а не из таймера.
3. Метаданные, обложка и длительность совпадают с реально проигрываемым файлом.
4. Мини-плеер и полный плеер всегда показывают одно и то же состояние (один store).
5. Треки без аудио **не имитируют воспроизведение**: прогресс не идёт, показано «No audio in this preview».
6. Демо-аудио явно помечено «Demo audio», атрибуция CC BY 4.0 доступна в приложении.

Вне области (отложено): фоновое воспроизведение, управление с экрана блокировки, выбор устройства вывода, сохранение позиции между сессиями (Фаза 3), стриминг с сервера.

## 4. Архитектура

### 4.1. Зависимость

`npx expo install expo-audio` в `apps/mobile` подберёт версию под SDK 57.

Свойства пакета:
- официальный пакет Expo;
- работает в Expo Go и на Web;
- конфиг-плагин для воспроизведения не нужен (он нужен только для фона или микрофона, а это вне области).

Меняются `apps/mobile/package.json` и `pnpm-lock.yaml`.

### 4.2. Модули

```
src/audio/audio-engine.ts     интерфейс AudioEngine + реализация на expo-audio (один глобальный плеер)
src/audio/demo-audio.ts       trackId → { source: require(mp3), credit }  (единственное место привязки)
src/state/player-store.ts     логика очереди; вместо setInterval — команды движку и события статуса
src/app/_layout.tsx           подключение движка при старте приложения (setAudioModeAsync + bind)
```

**Интерфейс движка** (позволяет тестировать store в Node без нативного модуля):
```ts
type EngineStatus = { currentTime: number; duration: number; playing: boolean; isBuffering: boolean; isLoaded: boolean; didJustFinish: boolean };
interface AudioEngine {
  load(source: AudioSource): void;   // player.replace(source)
  play(): void; pause(): void;
  seekTo(sec: number): void;
  setLoop(on: boolean): void;        // для repeat 'one'
  onStatus(cb: (s: EngineStatus) => void): () => void;
}
```

Реализация:
- `createAudioPlayer(null, { updateInterval: 250 })` — один экземпляр на всё приложение. Используется `createAudioPlayer`, а не хук, потому что плеер должен жить дольше любого экрана.
- Статус через `player.addListener('playbackStatusUpdate', …)`.
- При старте `setAudioModeAsync({ playsInSilentMode: true })`, чтобы на iOS звук не глушился переключателем «без звука».

`player-store.ts` получает движок через `bindAudioEngine(engine)`. Пока движок не привязан (тесты, SSR), используется пустой движок без побочных эффектов.

### 4.3. Состояние плеера

Добавляется:
```ts
playback: 'idle' | 'loading' | 'playing' | 'paused' | 'unavailable' | 'error';
durationSec: number | undefined;   // из движка; до загрузки — из каталога
```

`isPlaying` остаётся (на него опираются эквалайзер, анимации, кнопки) и вычисляется как `playback === 'playing'`.

Удаляется:
- `tickHandle`;
- `startTicking`;
- `stopTicking`;
- `stopPlayerTicking`.

### 4.4. Поведение

| Действие | Трек с аудио | Трек без аудио |
|---|---|---|
| `play(id, queue)` | `load` → `play`; `playback = 'loading'`, затем `'playing'` по статусу | `playback = 'unavailable'`, движок ставится на паузу, `progressSec = 0` |
| `togglePlayPause` | `play()`/`pause()` движка | ничего не делает (кнопка неактивна) |
| `seekTo(sec)` | `engine.seekTo`, прогресс из статуса | ничего не делает |
| Next/Previous | переход; новый трек грузится и играет | переход на трек → `'unavailable'` (без автопропуска) |
| Конец трека (`didJustFinish`) | `repeat 'one'` → движок в loop; иначе `next()` | — |
| Ошибка загрузки | `playback = 'error'`, сообщение «Couldn't play this track» | — |

Правила, которые сохраняются:
- Previous при >3 с возвращает в начало.
- Shuffle, repeat 'all', очередь, удаление из очереди, лайки — без изменений.

[П] Без автопропуска треков без аудио: пользователь видит честное «No audio in this preview» на том треке, куда перешёл. Автопропуск скрывал бы, что большинство треков пока без звука.

### 4.5. Плавный прогресс

`useSmoothProgress` сейчас рассчитан на шаг 1 с. При `updateInterval: 250`:
- `TICK_MS` → 250;
- порог «это перемотка» остаётся.

Интерполяция идёт только между реальными значениями движка.

## 7. Тесты и проверка

**Автотесты** (`scripts/verify-player-store.mjs`, `tsx`, с тестовым движком, который записывает вызовы; используются реальный store и реальная логика):
1. `play` трека с аудио → `load` нужного источника и `play`; `playback` идёт через `'loading'` → `'playing'` по статусу.
2. `play` трека без аудио → `'unavailable'`, движок не запускается, прогресс 0.
3. Статус движка → `progressSec`/`durationSec` в store.
4. `didJustFinish` → `next()`; с repeat 'one' → loop, без перехода.
5. `seekTo` передаётся движку и ограничивается длительностью.
6. Previous: >3 с → в начало; иначе предыдущий трек.
7. Next на трек без аудио → `'unavailable'`, звук остановлен.
8. Ошибка загрузки → `'error'`.

Существующие тесты, завязанные на таймер, переписываются под движок; остальные не меняются.

**Expo Web, 390 px:**
- Реальное воспроизведение: позиция растёт только когда движок играет, на паузе не растёт.
- Pause/Play, Next/Previous между двумя демо-треками.
- Перемотка скраббером.
- Окончание трека → следующий.
- Синхронизация мини-плеера и Now Playing.
- Трек без аудио: «No audio in this preview», неактивный Play.
- Лист кредитов.
- Консоль без ошибок.
- **Слуховую проверку делает пользователь:** у меня нет вывода звука, я проверяю состояние медиа-элемента.

**Нативно:** не проверяется — симуляторов нет. В отчёте разделяется «проверено на Expo Web» и «не проверено нативно».

Плюс typecheck, lint, все тесты, сборка Expo Web, `git diff -- apps/api` пуст, локальный коммит без push.

## 8. Риски

| Риск | Мера |
|---|---|
| Политика автозапуска браузера | Воспроизведение запускается только по нажатию; первый запуск после перезагрузки страницы требует тапа (честное поведение). |
| Длительность в каталоге ≠ файлу | Обновляется `durationSec` двух треков; после загрузки — значение движка. |
| Тесты в Node не могут загрузить нативный модуль | Внедрение движка через интерфейс; в тестах — тестовый движок. |
| Плеер «живёт» после ухода с экрана | Один глобальный `createAudioPlayer`; намеренно не освобождается за время жизни приложения. |
| Размер бандла +13,6 МБ | Принимается для демо; опция перекодирования. |
| Совместимость версии expo-audio с SDK 57 | Ставится через `npx expo install`. |
| Фон/экран блокировки | Вне области; на iOS звук остановится при сворачивании (ожидаемо для этого этапа). |
