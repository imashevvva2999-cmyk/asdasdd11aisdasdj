# W3 — Floating Canvas: спецификация реализации

> Дата: 2026-10-08. Статус: **на утверждение**. Код приложения не менялся.
> Основание: вы утвердили визуальное направление Concept D (iPhone и десктоп) и попросили финальную доработку дизайна и план реализации.
> Макеты: `2026-10-08-w3-concept-d.md`, `2026-10-08-w3-concept-d-iphone.md`, `w3-concepts/`.
> Подробный пошаговый план первого этапа (iPhone): `docs/superpowers/plans/2026-10-08-w3-stage1-iphone.md`.

## 1. Цель и границы

**Цель:** один сайт с единой системой Floating Canvas для телефона, планшета и десктопа: сцена цвета обложки, плавающая навигация, капсула плеера, одно непрерывное движение Home → Now Playing.

**Неизменно:**
- все работающие функции и жесты Dynamic Premium Player;
- сторы (`player-store`, `library-store`, `playlists-store` и др.), очередь, shuffle и repeat, звук W2;
- маршруты: `/player/now-playing`, `/player/lyrics`, `/player/queue`, `/sheets/*`;
- `apps/api` не трогаем.

**Без:**
- новых зависимостей;
- push и деплоя;
- новой символики MBANK;
- выдуманных экранов и выдуманных текстов песен.

## 2. Финальные доработки дизайна (предлагаю утвердить вместе с планом)

### 2.1. Desktop Now Playing — вертикальный ритм

Обложка и контент центрируются по вертикали между пилюлей сверху и капсулой снизу. Пустые зазоры уходят, новых элементов нет.

| Элемент | Размер / отступ |
|---|---|
| Обложка | `min(52vh, 460px)`, соседние треки видны по краям, меньше на 20 % |
| Обложка → название | 32 px |
| Название | 64 px (при высоте окна < 800 — 52 px), исполнитель 18 px |
| Название → тихий ряд (♡ Liked · Lyrics · Queue) | 16 px |
| Тихий ряд → строка в фокусе (3 строки текста) | 24 px |
| Строка в фокусе → капсула | не меньше 24 px |

- При низком окне (< 760 px) строка в фокусе скрывается первой, затем уменьшается обложка.
- Коралловый Play / Pause — единственный акцент.

### 2.2. Desktop Lyrics — читаемость

Lyrics остаётся отдельным погружающим видом (маршрут `/player/lyrics`).

| Правило | Значение |
|---|---|
| Колонка текста | по центру экрана, ширина до 720 px (около 34 символов в строке при 40 px) |
| Выравнивание | **по левому краю** внутри колонки: длинные строки и переносы читаются легче, чем при выравнивании по центру |
| Размер | 40 px на ≥ 1280, 34 px на 1024–1279, 28 / 32 pt на телефоне (текущая строка) |
| Межстрочный интервал | 1.25; между строками песни 0.6 em |
| Текущая строка | белая, 100 %; соседние 55 %; остальные 32 % (контраст проверяется на каждой палитре) |
| Автопрокрутка | текущая строка держится на 35 % высоты области текста |
| Ручная прокрутка | автопрокрутка останавливается и возвращается через 4 с без прокрутки |
| Синхронизация | подсветка только у текста с метками времени; текст без меток показывается целиком, без подсветки |
| Управление | капсула внизу всегда видна, музыка не прерывается |

- Обложка — карточка трека 56 px слева вверху.
- Переключатель Lyrics / Queue — справа вверху.

### 2.3. Меню ⋯ — одно на весь плеер

**Предложение:** на десктопе и планшете оставить **один** ⋯ — в капсуле, а ⋯ в верхней пилюле убрать. Две одинаковые кнопки с разным содержимым путают.

Состав меню (группы разделены тонкой линией):
1. Shuffle (Off / On), Repeat (Off / All / One);
2. Lyrics `L`, Queue `Q`;
3. Add to playlist, Support artist, View artist, Go to album, Share track;
4. Audio quality.

- Пункты третьей группы — это существующие действия листа Options; новых нет.
- **Телефон (< 600):** shuffle и repeat видны в плеере, ⋯ в шапке открывает существующий лист Options (Add to playlist остаётся в нём).

**Размещение:**
- **Не меньше 600 px:** всплывающее меню над кнопкой ⋯.
  - Позиция считается функцией `placeMenu` (тестируется): меню не перекрывает капсулу и не выходит за окно, отступ от краёв 16 px.
  - Если места сверху мало, меню открывается со сдвигом влево и ограничивается по высоте с прокруткой.
- **Меньше 600 px:** нижний лист (существующий `SheetScreen`).
- **Закрытие:** Esc, клик вне меню, выбор пункта. Фокус возвращается на ⋯.
- **Клавиатура:** ↑ / ↓ по пунктам, Enter — выбор.

### 2.4. Текст песен — только реальные данные

Правило выбора (функция `lyricsStateFor`, тестируется):

| Данные трека | Что показывается |
|---|---|
| Есть текст в каталоге (`mocks/lyrics.ts`) | Текст; подсветка, если есть метки времени |
| Нет текста, играет демо-аудио | «Lyrics unavailable for demo audio» / «This demo recording is instrumental.» |
| Нет текста и нет демо-аудио | Текущее пустое состояние «Lyrics unavailable» |

- Тексты-заглушки из макетов (Horizon) в приложение **не попадают**.
- Строка в фокусе в плеере показывается только для первого случая; иначе её место не занимается.
- ⚠ **Вопрос OQ-W3-1** (см. §9): у Midnight Mirage в каталоге есть синхронизированный mock-текст, но играет инструментальное демо-аудио.

### 2.5. Единая адаптивная система

| Класс | Ширина | Навигация | Управление | Now Playing | Lyrics / Queue |
|---|---|---|---|---|---|
| **Телефон** | < 600 | Пилюля Home / Search / Library снизу | Сцена на Home; капсула над пилюлей, когда сцены не видно | Полный экран, жесты как сейчас | Отдельный экран, общий заголовок и переключатель, управление снизу |
| **Планшет** | 600–1023 | Пилюля сверху по центру | Капсула внизу по центру (компактная: ⏮ ⏯ ⏭, прогресс, ⋯) | Портрет: одна колонка; ландшафт: обложка слева, текст справа | Как телефон, шире поля |
| **Десктоп** | ≥ 1024 | Пилюля сверху по центру | Капсула: ⏮ ⏯ ⏭, время, шкала, громкость, ⋯ | §2.1 | §2.2 |

**Ввод:**
- **Сенсор:** все жесты Dynamic Premium; всё, что показывается при наведении, доступно касанием.
- **Мышь:** перетаскивание обложки (курсор «рука»), клик по шкале, наведение на обложку поднимает её на 4 px.
- **Трекпад:** горизонтальный свайп двумя пальцами по обложке листает треки — не чаще одного раза за жест. Вертикальная прокрутка страницы не перехватывается.
- **Клавиатура:** набор из `2026-10-08-w3-responsive-design.md` §6.2, но F открывает и сворачивает плеер, L / Q переключают вид.

**Громкость:**
- только на десктопе с мышью;
- на iOS Safari громкость сайта задать нельзя, поэтому на сенсорных устройствах регулятора нет.

## 4. Этапы реализации

Каждый этап — отдельный план, отдельные коммиты и ваша проверка перед следующим. План этапа 2 и 3 пишется после приёмки предыдущего: он опирается на реальные интерфейсы, а не на догадки.

### Этап 1 — iPhone и мобильный браузер (< 600 px)

Подробный план: `docs/superpowers/plans/2026-10-08-w3-stage1-iphone.md`.

1. Чистая логика с тестами:
   - тона сцены (`stage-tones`);
   - геометрия перехода (`stage-math`);
   - выбор текста песни (`lyrics-state`).
2. Фон сцены: четыре тона и виньетка (в Now Playing и в слое раскрытия).
3. Lyrics: правило §2.4, пустое состояние демо-аудио, автопрокрутка, общий заголовок и переключатель Lyrics / Queue, управление снизу.
4. Queue: тот же заголовок и переключатель. Autoplay, удаление из очереди, ⋯ и подсветка играющего трека сохраняются.
5. Now Playing (телефон):
   - приглушённые shuffle / repeat;
   - тихий ряд Lyrics / Queue / Support / Audio;
   - одна строка текста (только при реальном тексте);
   - вертикальный ритм.
6. Навигация: пилюля Home / Search / Library вместо полосы вкладок; капсула над ней (бывший мини-плеер с теми же жестами).
7. Home-сцена: карусель 256 pt, название, ⏮ ⏯ ⏭, прогресс, ♡ / Lyrics / Up next; капсула скрыта, пока сцена видна. Пустое состояние — по решению OQ-W3-2.
8. Переход сцена → Now Playing (≈ 350 мс): обложка растёт из сцены, элементы Home уходят вниз и гаснут, пилюля опускается. Свайп вниз — обратно. Из капсулы — как сейчас.
9. Проверка и регрессия (§6), сравнение с макетами, отчёт.

### Этап 2 — планшет (600–1023, портрет и ландшафт)

1. Классы раскладки (`layoutClassFor`, `useLayoutClass`); колонка 480 px остаётся только для телефона.
2. Пилюля сверху, капсула внизу по центру, отступ контента под капсулу.
3. Всплывающее меню ⋯ с `placeMenu` (тестируется), нижний лист на телефоне.
4. Now Playing: портрет — одна колонка; ландшафт — обложка и текст рядом. Все сенсорные жесты.
5. Home: сцена компактнее, «For you» в 4 колонки.
6. Проверка: 768 × 1024, 1024 × 768, 820 × 1180, 1180 × 820; поворот экрана без потери состояния.

### Этап 3 — десктоп (≥ 1024)

1. Капсула: ⏮ ⏯ ⏭, время, шкала 400 px, громкость (`setVolume` в браузерном движке, тест в `verify-browser-audio`), ⋯.
2. Now Playing: §2.1, соседи карусели видны всегда, перетаскивание мышью, свайп трекпадом.
3. Lyrics: §2.2.
4. Клавиатура: горячие клавиши, Tab-порядок, Skip to content, возврат фокуса.
5. Наведение и фокус: подъём обложки, Play на карточках, белое кольцо фокуса 2 px.
6. Проверка: 1024, 1280, 1440, 1920; высота 700 и 900.

### 6.2. Проверка в браузере (Playwright MCP — уже используется; без новых зависимостей)

**Жесты (390 × 844 и 360 × 740; на этапах 2–3 также планшет и мышь):**
- свайп обложки ← → на сцене, в плеере, в капсуле: трек и цвет меняются за пальцем, звук через 180 мс;
- неполный свайп возвращается;
- край очереди упирается, с repeat-all — переход по кругу;
- тап по обложке сцены, свайп вверх по капсуле и тап по капсуле открывают плеер;
- свайп вниз, ⌄, Back и Esc закрывают его;
- перетаскивание шкалы перематывает один раз при отпускании;
- Lyrics: прокрутка текста не закрывает плеер.

**Воспроизведение:**
- Play / Pause, Next / Previous, repeat-one, shuffle (порядок в Queue), autoplay;
- блокировка автозапуска iOS — пауза, без ошибки;
- Media Session.

**Навигация:**
- все вкладки, Artist, Album, Playlist, Profile, листы;
- прямые ссылки `/player/lyrics`, `/player/queue`;
- 404;
- история браузера вперёд и назад.

**Адаптивность:** 360, 390, 430, 768, 820, 1024, 1180, 1280, 1440, 1920; низкие окна 700. Нет горизонтальной прокрутки, нет обрезания и наложений (капсула и меню, пилюля и контент).

**Доступность:**
- reduce motion: проявление вместо движения, кроме движений под пальцем;
- контраст;
- фокус;
- подписи кнопок;
- цели нажатия ≥ 44 px.

**Гидратация:** 0 ошибок #418 / #425 в консоли на всех маршрутах (как после исправления #418).

## 7. Технические риски и компромиссы

| Риск | Мера |
|---|---|
| **Мигание раскладки на планшете и десктопе.** Статический HTML рендерится для ширины 0 (телефон), десктоп перестраивается после гидратации | Этап 2: оболочка скрыта до гидратации (`useHydrated`, уже есть) с фоном нужного цвета, либо CSS media queries в `+html.tsx` для каркаса. Замер на медленном соединении |
| **Переход «сцена → плеер»** требует знать положение обложки на Home | Прямоугольник обложки измеряется при раскладке и при прокрутке в shared value; если сцена не видна, раскрытие идёт из капсулы, как сейчас |
| **Замена полосы вкладок пилюлей** (`expo-router` Tabs) | Собственный `tabBar` у существующих Tabs — маршруты и стеки вкладок не меняются |
| **Конфликт жестов:** горизонтальный свайп сцены и вертикальная прокрутка Home | Пороги из `gesture-math` (`activeOffsetX` 12, `failOffsetY` 10) — те же, что у работающей карусели |
| **Свайп трекпадом** легко срабатывает дважды | Один шаг на жест: накопление `deltaX`, порог, пауза 400 мс |
| **Громкость на iOS** не управляется сайтом | Регулятор только для мыши (`pointer: fine`) |
| **Размер файлов:** `now-playing.tsx` вырастет | Раскладки телефона и десктопа — отдельные компоненты в `components/player/`, файлы < 500 строк |
| **Производительность:** цвет и движение | Все анимации на UI-потоке (shared values), как сейчас; без размытия и теней на анимируемых слоях |
| **Изменение текущего плеера** | Только после вашего утверждения этого плана; каждый шаг отдельным коммитом, его можно откатить |

**Компромиссы:**
- Один ⋯ вместо двух (§2.3): проще, но действия Options на десктопе становятся на один клик дальше от верхней строки.
- Текст песни на экране Lyrics — по левому краю (§2.2), а строка в фокусе в Now Playing — по центру под названием. Разное выравнивание оправдано: длинный текст читается с левого края, короткий фрагмент под центральной обложкой — по оси.

## 8. Порядок работы и контроль

1. Вы утверждаете эту спецификацию и план этапа 1.
2. Этап 1 выполняется по шагам; после каждого шага — тесты, typecheck, lint, сборка, локальный коммит.
