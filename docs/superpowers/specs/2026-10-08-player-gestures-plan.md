# Плеер Mmusic: жесты (горизонтальная карусель + вертикальное раскрытие) и адаптивный фон — план реализации

**Статус:** утверждён пользователем 2026-10-08 (решения — §11a). Шаг 0 выполнен на Expo Web — §12; ожидается проверка на устройстве и утверждение перехода к шагу 1.
**Дата:** 2026-10-08. **Основа:** коммит `90015bf`. Продолжение `2026-10-08-premium-player-redesign-research.md`.

**Решения пользователя (2026-10-08):**
- Направление — концепция C (Dynamic Premium) **без лишнего стекла и свечения**.
- **Главная цель — интерактивный горизонтальный свайп из видео-референса.**
- Плюс вертикальные жесты: развернуть и свернуть плеер.
- Коралловый акцент для основных действий сохраняется.
- Всё должно работать на реальных iOS и Android.

## 1. Повторный разбор видео: механика жестов

Кадры через 0,1–0,25 с, увеличение экрана телефона. «Наблюдаемое» — факт из видео, «Предложение» — наше решение.

| Аспект | Наблюдаемое | Предложение для Mmusic |
|---|---|---|
| Направление | Палец тянет обложку **влево** → текущая уходит влево, следующая въезжает справа (= Next). Вправо — назад | Так же: влево = Next, вправо = Previous |
| Следование за пальцем | Обложка смещается вместе с пальцем; между обложками виден зазор ~16 pt | 1:1 за пальцем, зазор 16 pt |
| Соседи | Во время свайпа видна часть соседней обложки | Соседи видны только во время жеста; в покое — только текущая |
| Темп | Пользователь листает быстрыми флик-жестами (~6 треков за 5 с); обложка «доезжает» за ~0,25 с | Коммит по скорости (флик) или по расстоянию; пружина без сильного перелёта |
| Смена данных | Название, артист и время меняются **в момент коммита**, а не в конце анимации. Во время перетаскивания остаются старыми | То же: `next()`/`previous()` вызываются при отпускании, если жест принят |
| Фон | Меняется **после коммита**, плавно ~0,4–0,5 с: оранжевый → лососевый → сиреневый (1,3 → 1,55 → 1,8 с). Во время перетаскивания не меняется | **Улучшение:** цвет следует за пальцем пропорционально смещению (синхронно со свайпом), после коммита доходит до палитры нового трека; при отмене возвращается |
| Загрузка | Новая обложка часто появляется как серый плейсхолдер, затем плавно проявляется | У нас обложки локальные. Соседние предзагружаются (`expo-image` prefetch), плейсхолдер — фирменный `CoverFallback` |
| Вертикальные жесты | **В видео нет** | Наше предложение (§4) |
| Мини-плеер | **В видео нет** | Наше предложение (§4, §5) |

## 2. Чего сейчас нет в Mmusic

| Взаимодействие | Сейчас | Нужно |
|---|---|---|
| Свайп по обложке | Нет. Обложка статична, трек меняется только кнопками | Горизонтальная карусель за пальцем, коммит/отмена, переход трека |
| Видимые соседи | Нет | Предыдущая и следующая обложки во время жеста |
| Адаптивный фон | Нет (фон `canvas`) | Палитра обложки, синхронизация со свайпом |
| Мини-плеер в палитре трека | Нет | Приглушённая палитра, тот же тайминг |
| Свайп вверх по мини-плееру | Нет. Только тап → маршрут `/player/now-playing` (системная анимация модального окна) | Интерактивное раскрытие за пальцем |
| Свайп вниз по плееру | Нет. Только кнопка «свернуть» | Интерактивное сворачивание за пальцем |
| Непрерывная обложка мини ↔ полный | Нет (два разных экрана) | Обложка «перетекает» из 44 pt мини-плеера в полноразмерную |
| Перетаскивание по прогресс-бару | Нет (только тап) | Нужно для разведения жестов (§6): скраббер должен «забирать» свои касания |
| Предсказуемый следующий трек при shuffle | Нет: `next()` выбирает случайный трек в момент нажатия — соседа нельзя показать заранее | Заранее рассчитанный порядок shuffle |

## 3. Горизонтальная карусель обложек

### 3.1. Поведение

1. Касание обложки → горизонтальное перемещение (`activeOffsetX ±12 pt`, `failOffsetY ±10 pt`). Обложка следует за пальцем 1:1, соседи с зазором 16 pt въезжают с краёв.
2. **Коммит**, если смещение > 35 % ширины или скорость > 600 pt/с в ту же сторону.
3. **Коммит Next** (свайп влево):
   - вызывается `next()` (реальная смена трека в `player-store`, загрузка аудио, сброс прогресса);
   - обложка доезжает пружиной (stiffness ≈ 260, damping ≈ 28, без заметного перелёта);
   - название, артист и время меняются сразу;
   - фон доходит до новой палитры.
4. **Коммит Previous** (вправо) — `previous()` с текущим правилом: после 3 с — перезапуск трека. Для свайпа вправо правило 3 с **не применяется**: жест всегда означает предыдущий трек. Кнопка ⏮ сохраняет прежнее поведение.
5. **Отмена** (мало и медленно) — пружиной на место; фон возвращается.
6. **Края очереди:**
   - нет следующего (repeat off, последний трек) → резиновое сопротивление (смещение × 0,3) и возврат;
   - repeat all → сосед — первый трек.
7. **Трек без аудио:** свайп на него разрешён; он становится текущим с честным «No audio in this preview», без автопропуска — решение Фазы 2.
8. **Пауза:** обложка остаётся уменьшенной (0,92), свайп работает так же.
9. **Во время анимации снапа** новый жест перехватывает обложку (быстрое листание, как в видео).

### 3.2. Устройство

- **`ArtworkCarousel`:** 3 слота (prev / current / next) на `expo-image`, общий `translateX` (Reanimated shared value), `Gesture.Pan` из `react-native-gesture-handler`.
- **Соседи** берутся из `player-store`: новый селектор `peekNeighbors()` → `{ prevId, nextId }` по той же логике, что `next()`/`previous()` (repeat, края). Единый источник — соседи всегда совпадают с тем, что реально заиграет.
- **Shuffle:** `next()` сейчас случайный в момент нажатия. Вводится `shuffleOrder` — перестановка очереди, рассчитанная при включении shuffle, — и `next()`/`previous()` идут по ней. Это же исправит расхождение экрана Queue с реальным порядком.
- **Без «прыжка» после коммита:**
  - при смене `currentIndex` в store слоты пересчитываются относительно нового индекса;
  - одновременно в `useLayoutEffect` к `translateX` добавляется ±ширина слота, чтобы картинка не дёрнулась, а затем пружина доводит до 0;
  - это главный риск горизонтального жеста; проверяется отдельно (§8).
- **Предзагрузка:** `Image.prefetch` для обложек соседей.
- **Логика решений** (коммит/отмена, сопротивление, порог скорости) — чистые функции в `src/lib/gesture-math.ts`, покрыты тестами.

## 4. Вертикальные жесты: раскрытие и сворачивание

### 4.1. Поведение

- **Мини-плеер:**
  - свайп вверх → плеер раскрывается вслед за пальцем;
  - тап — как сейчас (раскрытие анимацией);
  - коммит > 30 % высоты экрана или скорость вверх > 700 pt/с.
- **Полный плеер:**
  - свайп вниз в любом месте, кроме скраббера и карусели, → сворачивается вслед за пальцем;
  - коммит > 25 % или скорость > 700 pt/с;
  - кнопка «свернуть», системная кнопка «назад» Android и Escape на Web — сворачивание той же анимацией.
- **Непрерывность** (одна общая величина раскрытия `p` от 0 до 1):
  - обложка интерполируется из рамки мини-плеера (44 pt, радиус 8) в рамку полной обложки (размер, позиция, радиус);
  - фон растёт из прямоугольника мини-плеера (радиус 14 → 0) до всего экрана, цвет — та же палитра;
  - содержимое мини-плеера гаснет при `p` 0–0,25, элементы полного плеера проявляются при `p` 0,55–1;
  - таб-бар уезжает вниз вместе с раскрытием.
- **Отмена** — пружиной в исходное состояние.
- **Воспроизведение не прерывается:** аудио-движок глобальный (Фаза 2), навигация его не трогает.

### 4.2. Устройство (переиспользуем навигацию)

Маршрут `/player/now-playing` и группа `player` (Lyrics, Queue) **сохраняются**: шесть мест вызова `router.push('/player/now-playing')`, Lyrics и Queue внутри плеера, листы поверх. Глобальный оверлей над навигацией отклонён — он перекрыл бы листы и модальные маршруты.

1. **Группа `player`:**
   - `presentation: 'fullScreenModal'` → `'transparentModal'`, `animation: 'none'`, `gestureEnabled: false`;
   - экран под плеером остаётся видимым, анимацию рисуем сами.
2. **Общее состояние раскрытия** — модуль `src/state/player-surface.ts`:
   - shared value `expandProgress`;
   - измеренная рамка обложки мини-плеера (`measure()` при показе мини-плеера);
   - флаг «плеер раскрыт».
3. **Свайп вверх по мини-плееру:**
   - жест активируется → `router.push('/player/now-playing')` без анимации;
   - экран плеера монтируется с `p`, равным текущему значению жеста;
   - продолжающийся жест на мини-плеере дальше двигает `p`;
   - отпускание → пружина к 1 или к 0; при 0 — `router.back()`.
4. **Сворачивание:**
   - жест на экране плеера двигает `p` вниз;
   - отпускание → пружина к 0, затем `router.back()` без анимации;
   - мини-плеер под ним скрыт, пока `p > 0`, чтобы не было двойной обложки.
5. **Кнопка «назад»:**
   - перехватывается `beforeRemove` (`preventDefault` → анимация сворачивания → `dispatch`);
   - так же работают системный жест «назад» Android и кнопка браузера.
6. **Открытие без жеста** (тап по треку в списке):
   - `p` анимируется 0→1 из рамки мини-плеера;
   - если мини-плеера на экране нет — из нижнего края.
7. **Риск передачи жеста** (п. 3): жест начался на мини-плеере, а сверху смонтировался экран плеера.
   - На iOS/Android активный распознаватель RNGH продолжает получать касания, на Web — по pointer capture. **Проверяется спайком в шаге 0** до основной работы.
   - **Запасной вариант:** во время перетаскивания раскрытие рисуется слоем внутри текущего экрана (тот же компонент `PlayerSurface`), а маршрут открывается без анимации только после коммита — визуально идентично.

## 5. Адаптивный фон и мини-плеер

- **Палитры** — заранее рассчитанные, контрастные (белый текст ≥ 5:1), как в исследовании §6.1. Источник — `src/constants/artwork-palettes.ts` + генератор (решение по инструменту — §11). Трек без палитры → палитра Mmusic по умолчанию.
- **Синхронизация со свайпом** (улучшение относительно видео):
  - пока палец тянет обложку, цвет фона = `interpolateColor(текущая ↔ соседняя палитра, |dx| / ширина)`;
  - после коммита доходит до 1 за время пружины;
  - при отмене возвращается;
  - при смене трека кнопками — переход 600 мс.
- **Фон полного плеера:**
  - анимируемый сплошной цвет;
  - статичный затемняющий градиент для читаемости нижней части;
  - **без размытия и без постоянного свечения** — по решению пользователя;
  - допускается только тонкая тень под обложкой.
- **Мини-плеер:**
  - `interpolateColor(surface L1 ↔ palette.mini)`;
  - прогресс в цвет акцента;
  - тот же тайминг;
  - **высота 60 pt не меняется**.
- **Коралловый** `#FF4B4B` — кнопка Play в полном и мини-плеере. Палитра не перекрашивает основные действия.

## 6. Разведение жестов (конфликты)

| Зона | Жест | Правило |
|---|---|---|
| Обложка в полном плеере | горизонтальная карусель | `activeOffsetX ±12`, `failOffsetY ±10` — вертикальное движение уходит в сворачивание |
| Остальной полный плеер | сворачивание вниз | `activeOffsetY +12`, `failOffsetX ±16`; внешний для карусели |
| Скраббер | перетаскивание для перемотки (новое) | собственный `Pan`, `blocksExternalGesture(сворачивание)` — перемотка не сворачивает плеер |
| Кнопки | тап | панорамы активируются только после смещения — тапы не конфликтуют |
| Мини-плеер | свайп вверх, тап | `activeOffsetY −10`, `failOffsetX ±16`; кнопки ⏭ и ▶ внутри — тапы |
| Списки под мини-плеером | вертикальная прокрутка | жест мини-плеера только на его площади; прокрутка списков не затрагивается |
| Системные жесты | iOS «домой» / Android «назад» с края | сворачивание через `beforeRemove`; край экрана не перехватываем |
| Нативный свайп модального окна iOS | — | отключён (`gestureEnabled: false`), заменён своим |

## 7. Доступность и reduce motion

- **Reduce motion:**
  - жесты по-прежнему следуют за пальцем (прямое управление — не декоративное движение);
  - после отпускания — короткий тайминг 120 мс без пружины;
  - смена цвета мгновенная при коммите;
  - раскрытие тапом — плавное появление вместо морфинга.
- **Кнопки** ⏮ ⏭, «свернуть» и тап по мини-плееру остаются — жесты дублируются.
- **Скринридеры:** у карусели `accessibilityRole="adjustable"` с действиями «increment/decrement» = Next/Previous; мини-плеер — действие «Expand player».
- **Контраст:** тест на каждую палитру.

## 8. Производительность и технические риски

| Риск | Вероятность | Мера |
|---|---|---|
| Передача жеста мини-плеер → экран плеера | Средняя | Спайк в шаге 0 на Web и устройстве; запасной вариант §4.2 п. 7 |
| «Прыжок» карусели при смене индекса после коммита | Средняя | Компенсация `translateX` в `useLayoutEffect`, проверка покадрово на Web и на устройстве |
| Конфликт сворачивания с каруселью и скраббером | Средняя | Пороги и `failOffset` (§6), `blocksExternalGesture`, ручная матрица проверок (§9) |
| Производительность морфинга | Низкая | Только transform/opacity/backgroundColor на UI-потоке; 3 изображения в карусели; без размытия |
| Рендеры React на каждом кадре | Низкая | Все значения — shared values; React-обновления только при коммите трека |
| Быстрое листание (несколько `next()` подряд) | Средняя | Каждый коммит — одна смена трека; загрузка аудио последнего трека отменяет предыдущую (`replace` в движке) |
| `transparentModal` на iOS/Android с прозрачным фоном | Низкая | Проверка на устройстве; экран под плеером остаётся смонтирован |
| Нативное поведение не проверить на этом Mac | **Высокая** | Обязательная проверка пользователем в Expo Go на iPhone и Android (§9). Вариант — установить Xcode Simulator / Android Emulator (большие загрузки, только с разрешения) |
| Регрессии Фазы 2 | Средняя | 64 проверки плеера + новые тесты + браузерная регрессия |

## 9. Тестирование

**Автотесты** (`tsx`, без новых библиотек):
1. `gesture-math`: коммит/отмена по расстоянию и скорости, сопротивление на краях, направление, пороги раскрытия и сворачивания.
2. `player-store`:
   - `peekNeighbors()` совпадает с тем, что реально делают `next()`/`previous()` (repeat off/all/one, края, shuffle);
   - `shuffleOrder` стабилен;
   - свайп-Previous всегда идёт к предыдущему треку.
3. **Палитры:** у каждой локальной обложки есть палитра; контраст ≥ 5:1; fallback.
4. **Существующие тесты** плеера (64), маршрутов, библиотеки — без регрессий.

**Expo Web (автоматизация chrome-devtools, 390 и 360 px):**
- Свайп обложки синтетическими pointer-событиями: Next, Previous, отмена, флик, край очереди, трек без аудио. Реальный звук меняется — проверка медиа-элемента, как в Фазе 2.
- Синхронизация цвета фона с позицией пальца (замер `backgroundColor` по ходу жеста).
- Раскрытие свайпом вверх, сворачивание вниз, отмена; кнопка «свернуть»; кнопка браузера «назад».
- Перемотка перетаскиванием не сворачивает плеер; кнопки работают.
- Мини-плеер синхронен; Lyrics, Queue, кредиты демо-аудио, листы открываются поверх.
- Reduce motion (`emulate` prefers-reduced-motion).
- Консоль без ошибок.

**Реальные устройства (обязательно, выполняет пользователь — у меня нет симуляторов):**
- Запуск в Expo Go на iPhone и Android (`npx expo start`, QR-код).
- Чек-лист (будет приложен к отчёту):
  - свайпы влево и вправо;
  - отмена;
  - быстрое листание;
  - раскрытие и сворачивание;
  - системная кнопка «назад» Android;
  - перемотка;
  - reduce motion в настройках ОС;
  - звук не прерывается.

Плюс typecheck, lint, сборка Expo Web, `git diff -- apps/api` пуст, локальные коммиты без push.

## 10. План реализации по шагам

Каждый шаг — отдельный коммит, проверка и короткий отчёт. После шагов 0, 3 и 5 — остановка на согласование со скриншотами/записью.

| Шаг | Содержание | Результат |
|---|---|---|
| 0. Спайк | Минимальный прототип в ветке-черновике: Pan на мини-плеере + `router.push` без анимации + продолжение жеста; карусель из 3 слотов с компенсацией индекса. Проверка на Web и в Expo Go (пользователь) | Подтверждение подхода §4.2 или переход на запасной. Код спайка не попадает в основную ветку |
| 1. Основа | `gesture-math`, `peekNeighbors`, `shuffleOrder` в store, палитры + генератор, `player-surface` (shared values) | Тесты зелёные, UI без изменений |
| 2. Адаптивный фон | Фон полного плеера и мини-плеера из палитры, переходы при смене трека кнопками | Визуальное изменение без жестов |

### 12.1. Горизонтальная карусель — подтверждено

| Сценарий | Результат |
|---|---|
| Медленный свайп влево / вправо (210 px) | Реальная смена трека (`next()` / предыдущий), звук играет; максимальный сдвиг за кадр 16 px (= шаг пальца), без скачков |
| Короткое медленное перетаскивание (60 px) | Отмена, обложка пружиной на место, трек не меняется |
| Флик (90–100 px, быстро) | Коммит по скорости, сдвиг за кадр ≤ 29 px |
| 24 быстрых флика сериями с интервалом 200/120/60/30 мс, включая захват обложки во время снапа и упор в край очереди | **Каждый флик засчитан, трек всегда верный**, обложки встают ровно по центру, звук играет |
| Трек без аудио | Становится текущим, честное «unavailable» (без автопропуска) |

**Найдено и исправлено в спайке (обязательно для реализации):**
1. **Скачок на 1 кадр (336 px) при смене трека.** Причина: React двигал слоты, а компенсация смещения приходила кадром позже.
   - Решение: слоты стоят на **фиксированных позициях по индексу очереди**;
   - при коммите базовое смещение полосы и смещение жеста меняются **одной атомарной операцией на UI-потоке** — экран в этот кадр не меняется.
   - После исправления скачков нет.
2. **Потерянные флики при быстром листании.** Причина: объекты жестов создавались заново на каждом рендере, и смена трека переподключала жест во время касания.
   - Решение: жесты создаются один раз (`useMemo`);
   - изменяющиеся значения (есть ли сосед) читаются из shared values.
3. **Неверное направление при флике во время снапа.** Решение: для флика решает направление скорости пальца, для медленного перетаскивания — пройденное расстояние.
4. **Web: картинки перетаскиваются браузером** (`dragstart` → `pointercancel`). Решение: у обложек `pointerEvents="none"`, касания получает контейнер жеста.
5. **Ошибки `play() was interrupted` при быстром листании** (безвредные, но шум в консоли и лишняя работа). Решение для реализации: интерфейс обновляется сразу, а загрузка и запуск аудио — после короткой паузы листания (~150–200 мс).

### 12.2. Вертикальные жесты — подтверждено, с выбором варианта

| Сценарий | Результат |
|---|---|
| Медленный свайп вверх по мини-панели | Плеер следует за пальцем; отпускание — раскрытие |
| Короткий свайп вверх (90 px) | Отмена, возврат, маршрут не остаётся открытым |
| Потянуть плеер вниз на 80 px | Следует за пальцем (89 px), возврат в раскрытое состояние |
| Потянуть вниз на 420 px | Следует за пальцем, сворачивание, маршрут закрыт |
| Флик вверх / флик вниз (реалистичный, 6 событий) | Раскрытие (скорость −1455 / −925 px/с) / сворачивание |
| Кнопка «назад» браузера при раскрытом плеере | Перехвачена: анимация сворачивания, затем закрытие маршрута |
| Тап по мини-панели | Раскрытие анимацией |
| Горизонтальный флик по мини-панели | Смена трека без раскрытия |
| Диагональ «в основном горизонтально» по мини-панели | Смена трека, без раскрытия (ось фиксируется по первому реальному движению) |

**Передача жеста** (жест начат на мини-плеере, во время жеста открывается маршрут плеера) **работает**: 19 обновлений получено после открытия, плеер следовал за пальцем. Но на Web монтирование маршрута во время жеста кратковременно блокирует единственный поток.

**Решение для реализации — запасной вариант §4.2 п. 7:**
- во время перетаскивания раскрытие рисуется лёгким слоем на текущем экране (та же палитра и обложка);
- маршрут `/player/now-playing` открывается после коммита, без анимации, в том же виде.

В спайке проверено: слой следует за пальцем, коммит открывает маршрут, отмена не открывает ничего. Тяжёлая работа не попадает в жест ни на одной платформе.

**Найдено и исправлено:**
- **ось жеста фиксируется по первому реальному движению**, а не в событии старта: на Web событие старта может содержать нулевое смещение;
- активация панели мини-плеера — `minDistance(10)` + фиксация оси;
- тап и панорама объединены через `Gesture.Exclusive(pan, tap)`.

### 13.2. Как устроено

- **Общая позиция** `carouselPos` в `state/player-surface.ts` управляет обложками, фоном полного плеера и тоном мини-плеера. Поэтому они не расходятся.
- **Store считает обороты** (`laps`) при переходе через край очереди с repeat all. `playPosition()` продолжает счёт (3 → 4), так что переход выглядит как обычный свайп.
- **Карусель** (`components/player/artwork-carousel.tsx`):
  - обложки стоят на фиксированных позициях;
  - жест создаётся один раз;
  - флик решает по скорости, медленное перетаскивание — по расстоянию (35 %);

- **Перемотка** (`components/player/seek-bar.tsx`):

- **Сворачивание:**
  - потянуть вниз в любом месте, кроме обложки (горизонталь) и шкалы;

- **Мини-плеер:**

### 13.3. Отличия от плана

- **Обложка при раскрытии** растёт из масштаба 0,6 в своей позиции, а не летит из рамки мини-плеера (44 pt). Причина: точный «полёт» требует измерения рамок на каждом экране, а результат и так выглядит цельным. Можно доработать отдельно.
- **Таб-бар** не уезжает отдельно: его перекрывает поднимающийся лист.
- **Движение 1:1 с пальцем** (`VERTICAL_TRAVEL = 1`). Пороги — доли высоты экрана, как в §4.1: раскрытие > 30 %, сворачивание > 25 %, флик > 700 pt/с.
- **Свайп по мини-плееру:** 200 pt = один трек, то есть коммит после ~70 pt или флика.
