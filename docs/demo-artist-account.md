# Демо-аккаунт артиста (только для разработки)

Демо-аккаунт **Solaris Echo** открывает заполненный кабинет артиста (Обзор, Аналитика, Продвижение, Studio Pro) без ручного создания артиста и загрузки треков. Предназначен для презентаций и UI-тестирования.

> [Т] Это **не** настоящая аутентификация: серверной авторизации в Mmusic пока нет. Демо-вход работает только в dev-сборке (`__DEV__`); в production-экспорте экран входа показывает «Демо-вход недоступен» (проверяется в `scripts/verify-routes.mjs`). Не включать в production без серверной аутентификации.

## Настройка логина (один раз)

1. В `apps/mobile` выполните:
   ```bash
   npm run demo:setup
   ```
2. Введите логин и пароль (пароль скрыт, минимум 10 символов, вводится дважды).
3. Скрипт записывает в `apps/mobile/.env.local` две строки — логин и **SHA-256 хеш** пароля. Сам пароль нигде не сохраняется и не выводится. Остальные строки файла не меняются; права файла — `600`.
4. Перезапустите dev-сервер:
   ```bash
   npx expo start --web --clear
   ```

`.env.local` не попадает в git (`.env*` в `.gitignore`). Не коммитьте его и не пересылайте. Чтобы сменить пароль — снова `npm run demo:setup`.

Ручной вариант: `node scripts/demo-password-hash.mjs "<пароль>"` выводит хеш для `EXPO_PUBLIC_DEMO_ARTIST_PASSWORD_SHA256`; логин — в `EXPO_PUBLIC_DEMO_ARTIST_LOGIN`.

## Вход и выход

- Вход: `http://localhost:<порт>/profile/demo-login` (или Настройки → «Демо-аккаунт артиста»). После входа — сразу кабинет артиста.
- Управление: баннер «ДЕМО» в кабинете → «Управление» (`/profile/demo-account`): открыть кабинет, **Сбросить демо-данные** (с подтверждением), выйти.

## Хранение

- Состояние демо-аккаунта хранится в `localStorage` браузера под ключом `mmusic:demo-artist` — отдельно от данных обычных пользователей. Переживает перезагрузку страницы и перезапуск dev-сервера.
- Изменения во время тестирования (загрузки, черновики, кампании, кошелёк) сохраняются; выход их не удаляет. «Сбросить демо-данные» возвращает исходный набор (версия фикстуры — `DEMO_FIXTURE_VERSION` в `src/demo/demo-fixture.ts`).

## Что внутри

- 12 релизов Solaris Echo (10 опубликовано, 1 на модерации, 1 черновик). 5 — треки альбома Horizon (Deluxe) с демо-аудио; 7 — демо-релизы без аудио (плеер честно показывает «недоступно»).
- Аналитика: блок «Обзор артиста · ДЕМО» с фильтрами 7/30/90 дней (`src/demo/demo-analytics.ts`) поверх аналитики по трекам. Слушатели за 30 дней = слушатели в Обзоре; стримы от промо = показы × CR кампаний из раздела Продвижение.
- Продвижение: активная кампания, кампания на модерации, черновик и 3 завершённые кампании — каждая открывает свою аналитику.
- Studio Pro: демо-тариф Studio PRO без списаний.

Все показатели — демонстрационные и помечены «ДЕМО».

## Обычные аккаунты артистов — сохранение в браузере (MVP)

[Т] Данные обычного (не демо) артиста — профиль, метаданные загруженных треков и их статусы, черновик кампании, история и пауза кампаний, демо-баланс промо-кошелька — сохраняются в `localStorage` этого браузера под ключом `mmusic:artist-account:<пользователь>` (`src/state/artist-account-persistence.ts`) и восстанавливаются после перезагрузки страницы.

> **Это временное хранилище конкретного браузера, а не аутентификация и не бэкенд.** Данные видны только в этом профиле браузера, пропадают при очистке данных сайта и не синхронизируются между устройствами. Пароли, токены и платёжные данные не сохраняются (реальных платежей в Mmusic пока нет). При появлении сервера это хранилище заменяется серверным API.

- Отдельно от демо-аккаунта Solaris Echo (`mmusic:demo-artist`) и Guest Preview: пока вошёл демо-аккаунт, сохранение обычного аккаунта приостановлено; в Guest Preview (`/demo/*`) оно не запускается вовсе. После выхода из демо или Guest Preview обычный аккаунт восстанавливается.
- При старте приложение сначала читает сохранённые данные и только потом начинает записывать — инициализация не затирает сохранённое.
- Повреждённые или устаревшие данные не загружаются: они переносятся в `…:invalid` (не удаляются), а приложение стартует с пустым аккаунтом.
- «Выйти» в профиле пока не выполняет реальный выход (нет сервера аутентификации) и данные артиста не удаляет.
